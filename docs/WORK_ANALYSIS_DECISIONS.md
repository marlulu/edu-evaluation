## 1. 视频时长上限

### 问题描述

系统应该支持多长的视频？超长视频如何处理？

### 方案对比

| 方案 | 时长上限 | 优点 | 缺点 |
|------|----------|------|------|
| A. 严格限制 | ≤ 10 分钟 | 处理快、成本低 | 无法支持长视频 |
| B. 中等限制 | ≤ 30 分钟 | 覆盖大多数场景 | 长视频仍需分段 |
| C. 宽松限制 | ≤ 60 分钟 | 覆盖更多场景 | 处理时间长、成本高 |
| D. 无限制 | 无上限 | 最灵活 | 资源消耗大、超时风险高 |

### 分析

**典型作业视频时长分布**：

```
0-5 分钟   ████████████████████ 40%  短演示、代码讲解
5-15 分钟  ████████████████ 35%      项目展示、实验记录
15-30 分钟 ████████ 18%              详细报告、完整演示
30+ 分钟   ███ 7%                    长报告、多部分作业
```

**成本估算（以 1080p 视频为例）**：

| 时长 | 文件大小 | 关键帧数 | API 调用 | 处理时间 | 成本估算 |
|------|----------|----------|----------|----------|----------|
| 10 分钟 | ~150MB | 20-30 | 30-50 | 2-3 分钟 | $0.5-1 |
| 30 分钟 | ~450MB | 50-80 | 80-120 | 5-8 分钟 | $2-4 |
| 60 分钟 | ~900MB | 100-150 | 150-200 | 10-15 分钟 | $5-8 |

### ✅ 推荐方案：B. 中等限制（≤ 30 分钟）

**理由**：

1. **覆盖 93% 的场景**：0-30 分钟覆盖绝大多数作业视频
2. **合理的处理时间**：5-8 分钟用户可接受
3. **成本可控**：单次处理 $2-4，可接受
4. **超长视频处理**：超过 30 分钟的视频提供分段上传选项

**实施细节**：

```python
VIDEO_MAX_DURATION_SECONDS = 30 * 60  # 30 分钟
VIDEO_MAX_SIZE_MB = 500

# 超长视频处理策略
if video_duration > VIDEO_MAX_DURATION_SECONDS:
    # 选项1: 自动分段处理
    chunks = split_video(video_path, chunk_duration=600)  # 10分钟一段
    # 选项2: 提示用户裁剪
    raise VideoTooLongError("视频超过30分钟，请裁剪或分段上传")
```

## 2. 关键帧提取策略

### 问题描述

如何从视频中提取最有代表性的关键帧？

### 方案对比

| 方案 | 方法 | 优点 | 缺点 | 适用场景 |
|------|------|------|------|----------|
| A. 固定间隔 | 每 N 秒提取一帧 | 简单、均匀分布 | 可能错过重要画面 | 变化均匀的视频 |
| B. 场景变化 | 检测画面变化提取 | 捕捉重要内容 | 计算量大 | 演示、教学视频 |
| C. I 帧提取 | 提取编码关键帧 | 快速、无损 | 可能不均匀 | 所有视频 |
| D. 混合策略 | 结合多种方法 | 最全面 | 复杂度高 | 高质量需求 |

### 分析

**各方法效果对比**：

```
固定间隔:  ▃ ▃ ▃ ▃ ▃ ▃ ▃ ▃ ▃ ▃  (均匀但可能错过重点)
场景变化:  ▁ ▁ █ ▁ ▁ █ █ ▁ ▁ █  (捕捉重要内容)
I 帧:     ▃ ▁ ▁ █ ▁ ▁ █ ▁ ▁ █  (依赖编码)
混合策略:  ▃ ▁ █ ▃ ▁ █ █ ▃ ▁ █  (最全面)
```

**处理时间对比（30 分钟视频）**：

| 方法 | 处理时间 | 提取帧数 | 质量评分 |
|------|----------|----------|----------|
| 固定间隔 | 30 秒 | 50 | 7/10 |
| 场景变化 | 2 分钟 | 30-60 | 9/10 |
| I 帧提取 | 10 秒 | 20-40 | 6/10 |
| 混合策略 | 2.5 分钟 | 40-70 | 9.5/10 |

### ✅ 推荐方案：D. 混合策略（场景变化 + 间隔兜底）

**理由**：

1. **智能捕捉重要内容**：场景变化检测能识别重点画面
2. **保证覆盖完整性**：间隔兜底确保不遗漏
3. **平衡质量和效率**：处理时间可接受

**实施细节**：

```python
def extract_keyframes_hybrid(
    video_path: str,
    max_frames: int = 50,
    scene_threshold: float = 0.3,
    min_interval: float = 5.0,
) -> List[Keyframe]:
    """混合策略提取关键帧"""

    # 第一步：场景变化检测
    scene_frames = detect_scene_changes(video_path, threshold=scene_threshold)

    # 第二步：间隔兜底（确保每 min_interval 秒至少有一帧）
    interval_frames = extract_by_interval(video_path, interval=min_interval)

    # 第三步：合并去重（时间戳相近的保留场景变化帧）
    merged = merge_frames(scene_frames, interval_frames, merge_threshold=2.0)

    # 第四步：限制总数（保留最重要的帧）
    if len(merged) > max_frames:
        merged = select_top_frames(merged, max_frames)

    return merged
```

## 4. 模型选择：云端 vs 本地

### 问题描述

使用云端 API 还是本地部署模型？

### 方案对比

| 维度 | 云端 API | 本地部署 | 混合方案 |
|------|----------|----------|----------|
| **部署难度** | ⭐ 简单 | ⭐⭐⭐ 复杂 | ⭐⭐ 中等 |
| **初始成本** | $0 | $5000-20000 | $2000-5000 |
| **运行成本** | $0.01/分钟 | 电费 + 维护 | $0.005/分钟 |
| **延迟** | 100-500ms | 10-50ms | 20-100ms |
| **质量** | ⭐⭐⭐⭐⭐ 最好 | ⭐⭐⭐⭐ 好 | ⭐⭐⭐⭐⭐ 最好 |
| **隐私** | 数据外传 | 数据本地 | 敏感数据本地 |
| **可用性** | 依赖网络 | 离线可用 | 灵活 |
| **扩展性** | 弹性扩展 | 需扩容 | 灵活 |

### 分析

**成本对比（月处理 1000 小时视频）**：

```
云端 API:
  语音识别: 1000 × 60 × $0.006 = $360
  图像理解: 50000 × $0.01 = $500
  文本分析: 100000 × $0.002 = $200
  总计: ~$1060/月

本地部署:
  GPU 服务器: $500/月 (租赁) 或 $15000 (购买)
  电费: $200/月
  维护: $300/月
  总计: ~$1000/月 (租赁) 或 $500/月 (摊销后)

混合方案:
  语音 (本地): $200/月
  图像 (云端): $500/月
  文本 (本地): $100/月
  总计: ~$800/月
```

**质量对比**：

| 任务 | 云端 API | 本地模型 | 差距 |
|------|----------|----------|------|
| 语音识别 (中文) | 95% | 92% | -3% |
| 语音识别 (英文) | 97% | 94% | -3% |
| 图像理解 | 92% | 85% | -7% |
| 文本生成 | 95% | 88% | -7% |

### ✅ 推荐方案：混合方案（关键任务云端 + 批量任务本地）

**理由**：

1. **质量优先**：关键分析使用云端高质量模型
2. **成本控制**：批量任务使用本地模型降低成本
3. **灵活扩展**：可根据负载动态调整
4. **隐私保护**：敏感数据可选本地处理

# 进度反馈机制
class VideoProcessingProgress:
    """视频处理进度追踪"""

    STAGES = [
        ("preprocessing", "预处理", 5),
        ("metadata", "提取元数据", 10),
        ("keyframes", "提取关键帧", 25),
        ("audio_extraction", "提取音频", 30),
        ("transcription", "语音识别", 60),
        ("image_analysis", "分析关键帧", 80),
        ("content_analysis", "内容理解", 90),
        ("result_merge", "整合结果", 95),
        ("completed", "完成", 100),
    ]

    def __init__(self, task_id: str):
        self.task_id = task_id
        self.current_stage = 0
        self.progress = 0

    def update(self, stage: str, detail: str = ""):
        """更新进度"""
        for i, (stage_id, stage_name, progress) in enumerate(self.STAGES):
            if stage_id == stage:
                self.current_stage = i
                self.progress = progress
                self._notify_progress(stage_name, detail)
                break

    def _notify_progress(self, stage_name: str, detail: str):
        """通知前端进度"""
        # 通过 WebSocket 或轮询发送进度
        send_progress_update({
            "task_id": self.task_id,
            "stage": stage_name,
            "progress": self.progress,
            "detail": detail,
        })
```

## 6. 结果存储策略

### 问题描述

分析结果和中间产物如何存储？保留多久？

### 方案对比

| 方案 | 存储内容 | 保留时间 | 存储成本 | 查询速度 |
|------|----------|----------|----------|----------|
| A. 全量永久 | 全部 | 永久 | 高 | 快 |
| B. 结果永久 | 仅结果 | 永久 | 中 | 快 |
| C. 分级存储 | 按重要性 | 分级 | 低 | 中 |
| D. 临时存储 | 临时 | 7天 | 最低 | 慢 |

### 分析

**数据类型和大小**：

| 数据类型 | 单视频大小 | 重要性 | 访问频率 |
|----------|------------|--------|----------|
| 原始视频 | 100-500 MB | 中 | 低 |
| 关键帧图片 | 5-20 MB | 高 | 中 |
| 语音转录 | 10-50 KB | 高 | 高 |
| 分析结果 | 5-20 KB | 最高 | 高 |
| 中间数据 | 50-200 MB | 低 | 极低 |

### ✅ 推荐方案：C. 分级存储（按重要性和访问频率）

2. **性能保证**：热数据快速访问

        # 记录存储信息
        self._record_storage({
            "path": path,
            "data_type": data_type,
            "size": len(data),
            "created_at": datetime.now(),
            "expires_at": self._calculate_expiry(policy["retention_days"]),
            "tier": policy["backend"],
        })

        return path

    def cleanup_expired(self):
        """清理过期数据"""
        expired = self._find_expired_records()
        for record in expired:
            self._delete_data(record["path"])
            self._delete_record(record["id"])


# 定时清理任务
@app.task
def cleanup_expired_storage():
    """每天凌晨清理过期数据"""
    storage_manager = StorageManager()
    storage_manager.cleanup_expired()
```

| 关键帧 | 7 天 | 30 天 | - | 展示需要 |
| 音频文件 | 7 天 | 30 天 | - | 审核需要 |
| 转录文本 | 7 天 | 30 天 | 永久 | 分析需要 |
| 分析结果 | 7 天 | 30 天 | 永久 | 核心数据 |
| 审计日志 | - | - | 永久 | 合规要求 |
